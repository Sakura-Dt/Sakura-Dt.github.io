## 诊断与表达规则

原版本的问题并非缺少文案，而是不同章节过多使用「前一句，后一句」的两行命题，英文口号与极小中文注释共存，项目和学习状态的真实信息容易退到次要位置。

最终规则：

- 首页保留核心命题，问候、学校与开发实践说明建立身份。
- 个人介绍直接使用身份、技术基础、关注方向与具体问题；取消内部条目的全局式编号。
- Python 保留核心句作为开场，后续状态改成分类、预览、确认与记录的实际行为。
- Web 使用响应式设计与布局调整的中文表达，必要技术名保留英文。
- 学习方向用单行「接下来学什么」，条目用学习对象命名，明确计划与未实现状态。
- 联系使用自然邀请「聊聊代码，或一个新想法」，不再延伸抽象主题词。
- 详情使用名词式标题、连续正文和中文目录，不再复制首页的两行口号。

完整最终文案及主要修改理由见 [copy-inventory.md](copy-inventory.md)。

## 字体系统

维持原有两种字体：Archivo 用于拉丁文字与品牌；Noto Sans SC 用于中文。权重范围400–700，正文400，标签通常400–500，标题500–600。中文正文使用正常字距，标题仅轻微收紧；英文品牌不再比中文主标题更大。

| 角色 | 桌面 | 手机 | 使用方式 |
| --- | --- | --- | --- |
| 首页／身份主标题 | 56–96px | 46–62px | 必要的视觉主体，中文优先 |
| 演出标题 | 42–72px | 32–42px | 根据场景内容设置；后续操作状态26–31px |
| 详情主标题 | 40–76px | 38px | 自然换行，不写死两行 |
| 章节标题 | 28–42px | 28px | 详情与作品索引 |
| 区域标题 | 22–32px | 20–22px | 技术基础、方向条目等 |
| 常规正文 | 16px | 15px | 两份详情与连续阅读正文 |
| 紧凑场景正文 | 13–15px | 12–13px | 固定画面中的信息区域 |
| 信息标签 | 12px | 11px | 有效索引、状态、说明 |
| 注释 | 11px | 11px | 有事实价值的辅助内容 |

例外保持明确：文件目录与计数使用10–12px，以适应真实的密集结果；手机品牌副标与重复身份注释使用8–10px；邮箱地址按独立联系版式设置。手机隐藏重复的品牌副行与非必要技术顶栏，不以继续压小字号解决拥挤。

正文行高1.85，详情较长正文最多1.9；窄区域1.6–1.8。正文最长36em，详情导语38em，部分说明更短。标题使用 `text-wrap: balance`，段落使用 `text-wrap: pretty` 与严格中文换行。核心标题的必要两行、命令、目录名与文件名保持原语义。

主入口是 `assets/css/type.css` 中的字体角色变量与区域映射；场景文件仍负责几何布局。结尾收缩标题从 CSS 获取字号端点，不再另写一组脱离系统的字号。

## 编号规则

三页主导航统一为：

1. `01 / 本人` → `#about`
2. `02 / 作品` → `#projects`
3. `03 / 学习方向` → `#next`
4. `04 / 联系` → `#contact`

作品另用「项目01 / 个人网站」「项目02 / Python文件整理助手」。详情内部01–04只用于该页目录；Python五个演出状态保留A–E。移除学习图形中的孤立「01 →」和详情中重复的巨大装饰数字，避免误读为全局编号。

## 内容维护与字体资产

`content/site.json` 集中330个内容条目，按身份与共享导航、首页、个人介绍、项目演出、学习与联系、两份详情、运行时反馈分组。少量技术数据与符号仍由结构承担，所有正文、导航、可访问名称、命令示例与交互反馈均来自内容文件。

`scripts/render_site.py` 生成三页HTML、真实首页预览与 `assets/js/copy.js`。运行时只加载必要反馈文案，不在客户端重复加载完整内容库，也没有增加文案网络请求。内容维护流程见 [content/README.md](../../content/README.md)。

原三个阶段的中文补充字体已经合并到一个共享子集，移除冗余文件和字体声明。当前中文子集117,924字节，拉丁字体44,316字节，覆盖全部当前中文文案。仍使用相同官方字体源、原许可与400–700权重；源文件SHA-256为 `a3041811a78c361b1de50f953c805e0244951c21c5bd412f7232ef0d899af0da`。没有替换字体设计。

## 动态设计保留与必要同步

四个场景的几何生成函数与原始滚动行程逐字节/逐值保持不变，核对记录见 [motion-preservation.json](motion-preservation.json)。动画关键点、速度、顺序与原生滚动方式不变。JS调整集中在：

- 将复制、筛选、动效开关与场景状态改为读取统一文案。
- 结尾文字的字号端点读取CSS角色变量。
- 同步Web演示的导航字号、字距、品牌副标，保留真实渲染。
- 修复字体/iframe较慢时可能误把初始about:blank当作真实首页的加载竞态；等待实际首页标记和load后再使用节点。

首页文字变化后，通过浏览器重新测量1440×900、768×1024与390×844的实际页面，更新布局端点和无脚本截图。Web中间状态仍是实测端点之间的布局插值，不声称每个中间构图都是CSS原生断点。

## 实际审查与修改

两轮以上实际浏览器审查，检查1440×900、1366×768、768×1024、390×844、360×800的主要动态状态。第二轮修正了放大文字后Python手机结果页日志与底部说明的相邻空间，缩短了说明并保留“示例文件”的真实限定。

两份详情在1440×900、768×1024、390×844、360×800下采用减少动效模式截取全页，检查完整段落、链接、代码与自然换行。删除重复巨大02后，正文层级与对比更清晰。
