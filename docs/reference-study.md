## R01 · 月行水上：同一个版式骨架，允许内容高速变化

最终选帧8张：`6 / 9 / 10.5 / 12 / 14 / 16 / 20 / 28s`。

| 时间 | 画面中可确认的形、字、色与层级 | 作用及可迁移方法 |
| --- | --- | --- |
| 00:06 | 近黑底，绿色数字时钟成为唯一大主体 | 信息集中；网站可只保留一句主张，不移植时钟 |
| 00:09 | 绿色发光圆体处于建筑顶部，红色局部与暗绿环境对照 | 大形决定视觉重心；不搬入月亮、异界或发光效果 |
| 00:10.50 | 蓝底，竖向灰阶人物窄窗；大黑字被裁切，白色姓名字沿窄窗排列 | 图形边界同时组织图像和文字；用项目预览窗口替代人物 |
| 00:12 | 更换人物/姓名，蓝色整版与窄窗语法保持 | 重复“规则”而非重复同一装饰，适合两项目的共同排版 |
| 00:14 | 白色场域中标识缩小，蓝色圆弧从右侧进入 | 负空间与边缘形状改变场景密度；网站用原创开口框建立出口 |
| 00:16 | 蓝色弧带内含人物，白底留出中心区域，细圆环穿过 | 同一形状既是主体又是遮罩；可使版框变成项目内容窗口 |
| 00:20 | 城市鸟瞰，白色圆形边界包围建筑；场景从平面变为空间 | 保留“围合”关系；网站使用二维布局，避免模拟航拍镜头 |
| 00:28 | 蓝色线性背景，矩形卡片有倾斜、远近与尺度差 | 用数量受控的图层形成层级，不复制卡牌或塔罗符号 |

**可确认的运动链**：10.37/10.86/11.36/11.86/12.33s 连续样本依次出现不同人物及姓名组。人物和字的内容变化很快，但纵向窄窗、裁切大字和蓝色底场不被每次重新发明；观者先读到“同一系列”，再感知个体变化。12.88–13.93s 转入白底黑色大标识，视觉面积和底色同时改变。采样不足以断定每次都是滑动、替换还是帧级遮罩，不能把所有切换描述成无缝 morph。

**补采的圆环链（实际连续播放）**：14.95s两条大蓝弧围住中央标识；15.56s白色中心保持、弧带位置改变；16.18s人物可见于蓝弧内部；16.78s转成整版蓝色，标识成为较小的前景组合；18.61–19.23s出现倾斜圆形地面与大字。几何先是内容容器，随后又成为整版场域的边界。这才是可以研究的“形状承担转场”，不是在页面上摆一个圆就等同于它。

**网站转译**：首屏的开口框收窄成为项目索引边界，进入两个项目时保持同一边界位置；Web 用视窗，Python 用计划表，同一个结构托住不同内容。滚动每推进一段只改变框宽、文字位置或内容层中的两项，避免所有对象同时飞入。姓名、学校和项目链接不随装饰遮罩消失。

**不迁移**：高频人物蒙太奇、版权标识、强拍点、视频里的秒级阅读要求。滚动用户会停住或倒退，原片剪辑不能直接写成自动播放时间轴。

**连续片段10.39–13.68s**：大厅背景可辨，人物与右上悬浮物位置关系变化，观看注意力被引向右侧；14.20s 切入红发人物近景。连续性来自前后视线方向与明暗关系，并没有证据表明此处使用大量 kinetic type。其文字主要让位于场景，与 R01 的字图同权明显不同。

**网站转译**：个人介绍安排成阅读停顿，保留大块空白，学习基础与探索方向分层；过渡到项目时，让一个“局部问题”变大成为主角。作品介绍无需一直运动，真正的项目需求和边界应获得静止阅读时间。

**不迁移**：人物表演、摄影景深、建筑3D、对白驱动的悬念；不得把先导PV的镜头语言误写成活动界面的操作规则。

| 00:28 | 碎片围合、局部亮背景与小字幕 | 前后景对比继续 |

10.37–12.07s 大片暗遮挡包住中心小标识；12.63–13.19s 城市从斜向开口露出。可转译为不盖住链接的二维开口过渡。机械、橙黑与碎片是其叙事场景的一部分，不能据此把所有鹰角设计约化成工业HUD；本项目不用这些符号。

## R08 · 实际UI录屏：入场有演出，稳态要让出操作权

最终选帧8张：`1 / 1.5 / 2 / 2.3 / 2.6 / 3 / 4 / 5s`。这些是同一入场过程的阶段，不是8个不同界面；00:06–00:28额外用于稳态对比。

| 时间 | 可确认状态 | 判断 |
| --- | --- | --- |
| 00:01 | 高亮人物剪影、细线与浅色背景 | 先建立主体轮廓 |
| 00:01.50 | 边缘蓝色大字与细线共同出现，中央人物仍高亮 | 展示字可以出画，但不能用作唯一功能标签 |

| 00:02.30 | 入场中间态，图层开始向可操作主界面过渡 | 具体裁切边界见附件；不假设像素级形态变换 |

## 跨参考的可执行原则

| 原则 | 已见依据 | 原创网页动作 | 不接受的替代品 |
| --- | --- | --- | --- |
| 重复语法，变化内容 | R01窄窗与不同人物/字组；R04红轮廓换图 | 同一开口框承接身份、Web视窗、Python计划表 | 复制圆形、旗帜、塔罗牌 |
| 运动需要宾语 | R05车辆退远时注释仍依附道路 | 注释只指向真实的“预览”“确认”“跳过” | 随机代码雨、漂浮粒子 |
| 一次只改变主要关系 | R02空间→近景→小物件 | 全景介绍→单个项目决策→实现边界 | 每层同时旋转、缩放、模糊 |
| 大字也是图形 | R01黑白大字与窄窗互相裁切 | 标题与矩形开口共用基线、边缘 | 超大英文与中文内容毫无关系 |
| 密度要有高低 | R06亮群像后转暗单主体；R08稳态 | 两处重点演出，中间正常阅读 | 每个章节都全屏固定 |
| 转场要有继承物 | R07斜向开口；R03照片与建筑 | 下一章继承上一章的一条边或一个窗口 | 色块无缘无故覆盖整页 |

这些是本次观察后提出的设计判断，不是声称鹰角内部存在这些命名的规范。滚动分镜中的比例、时长、文案和图形均为原创方案，不能写成对PV的精确复刻。

## 对当前网站的重新诊断

基于当前工作区源码和上一轮真实渲染记录：

- `main.js` 的项目装饰由 IntersectionObserver 入场后增加 `is-composed`，属于一次性 scroll-triggered；没有把动画进度与滚动距离绑定。
- 首屏切圆、Web封面的S、Python纸片、结尾箭头彼此没有“前一个动作为什么导向后一个”的关系。
- “构想，逐步成形”“保持好奇”“WHAT'S NEXT”各自成立，但没有持续推进一个问题；英文展示字与具体项目决策联系不足。
- 初版已经具备可读性与降级策略，下一轮应保留；艺术指导升级不能以重新隐藏正文、延迟按钮为代价。

对应处方：将一个**可修订的开口版框**作为全站视觉语法，用“先写—起点—展开—核对—待续—来信”组织章节；让滚动改变框与内容之间的关系，而不是依次播放六次淡入。
