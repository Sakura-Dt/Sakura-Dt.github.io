## 真实页面，而非设备示意

删除旧版手工绘制的FORM浏览器模型。新演出由真实首页的HTML、字体、样式和SVG构成：生成器从当前首页提取导航与开场，生成只读首屏渲染，避免项目展示再次嵌套自己。页面内容没有另写一套虚构模板。

先在实际浏览器中测量1440×900、768×1024和390×844三个真实构图。测量值包括标题、身份、导航、署名、元信息的边界、字号、行高、间距及折面顶点，保存在 `assets/previews/layouts.json`。原始可读数据见 `source-layouts.json`。

演出始终使用同一份DOM。标题、导航、折面、个人信息分别插值，页面可视宽高也随之改变；外部镜头只负责将画面放入展示空间。三个端点来自实际页面，中间是为演出设计的连续布局插值，不声称首页原生CSS在每个中间宽度都采用这套插值规则。

只读渲染副本会冻结原首页的尺寸、滚动和媒体查询监听，防止原时间轴与外层插值争用；真实首页和Python的监听逻辑保留。单独打开原始渲染时解除这一冻结。主要入口仍链接完整的真实首页。

## 三个构图与空间叙事

- A / Desktop：深色画布上展开完整的桌面首屏，保留真实导航、中文主标题、图形、身份及署名。尺寸标尺和旁注说明布局关系，没有虚构设备外壳。
- B / Transformation：横向空间逐步重组，标题、图形和身份分别变化。到768px端点仍保留完整导航；缩窄后原导航被裁切聚合，实际菜单入口出现。注释沿独立的连续路径移动。
- C / Mobile：同一个页面形成纵向阅读顺序，中文两行主标题、完整折面和身份依次排列。外层构图改为左侧命题与右侧手机比例页面；手机观看时保留完整纵向画面。

Web展示采用深色空间、比例与标尺；Python仍采用文件、分类带、预览清单与目录。两章没有复用相同的动画模板。

桌面、平板和手机的演出行程分别为1660、1450、1150px。原生滚动与有限sticky区间结合，未拦截滚轮或触摸。局部五次缓动与45–65ms跟随，停下后精确落定并停止排帧。A/B/C按钮使用同一个进度；减少动效时提供瞬时切换的静态构图。无JavaScript时使用实际浏览器截图和完整项目文字。

## 两轮实际视觉审查

第一轮先建立桌面、平板、手机观看环境下的三个静态关键构图并实际截图。发现标尺与标题距离不足、说明在布局切换点存在位置跳变、页脚说明接近页面渲染边缘。分别整理标题和测量区、建立连续注释路径、移动说明到独立底部带，并补齐新增中文。

第二轮连接滚动后，实际检查1440×900、768×1024、390×844的0/.25/.50/.75/1及反向位置。进一步修正760px附近链接最小高度的6px突变，以及窗口从桌面改为手机后注释遗留定位的问题。临界点补验中发现的脚本引号错误已修复，重新通过语法与浏览器验证。

在768px中间构图附近，前后两个相邻滚动像素的关键元素几何差为0；跨760px的759.746/760.230两个实际宽度之间，关键元素最大变化为0.40625 CSS px，没有断点跳变。原始数据在附件 `boundary-verification.json`。

详情长图采用减少动效的阅读模式；普通固定演出以逐帧截图和录屏呈现，避免将滚动占位误认为空白内容。

## 复现与维护

```bash
python3 scripts/render_site.py
python3 -m http.server 8000 --bind 127.0.0.1
```

打开 http://localhost:8000/#web 或 http://localhost:8000/portfolio.html 。

如果未来主动修改首页构图，在本地服务运行时执行：

```bash
node scripts/measure_web_layouts.cjs http://127.0.0.1:8000
python3 scripts/render_site.py --check
npm test
```

测量工具使用项目的Playwright；可通过 `TEST_BROWSER_CHANNEL=msedge` 选择已安装的Edge。它会更新实测布局与无脚本后备截图。生成器同步真实首页片段，浏览器测试防止测量值与实际首页脱节。

交付附件 `review.html` 汇总三种观看尺寸的关键帧、三段正反向录像、真实首页端点原图与详情阅读长图。
