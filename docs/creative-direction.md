# TASK 01 · 三种原创方向与艺术指导建议

状态：待用户审查。不是已批准的开发方向。本轮不改变网站。证据与限制见 [参考研究](./reference-study.md)。

## 定位：一个有判断、有过程的学生作品集

优先服务两种访问：面试官快速确认身份、技术、项目和联系方式；愿意深入的人能沿着滚动看到“一个想法怎样被写成可以使用的东西”。艺术感来自二者共用一套构图与语言，而不是让访问者先看完一支宣传片。

当前内容规模是两个已实现项目、一个计划项目。没有作品数量、团队经历或职业成就足以支撑大型工作室口吻。应呈现正在建立的方法，而不是宣称完整成熟的技术体系。名字 Sakura 不自动等于樱花视觉，也不需要虚构人格、代号或世界观。

## A · 未定稿 / OPEN DRAFT — 首选

**一句话**：作品可以先有第一版，但每一次修改都应该有依据。

不是把“未完成”包装成借口；是把已有实现、经过判断的修订和明确留下的下一步公开给人看。网站、Python工具的功能边界、用户对网站的反复反馈，都是这个主题的真实材料。

### 视觉母题与构图

用一组**开口版框、基线与两层略微错位的字**建立身份。开口表示仍可修订；对齐表示一次判断暂时落定。矩形边界既能成为网页视窗，也能成为文件预览表、计划项目的空白位置，不需要凭空解释切圆的意义。

首屏：左上小姓名/学校；左侧中文“先写一版。”占主导；右侧一张未完全对齐的文字版面；底部是真实方向和直接作品入口。画面保留约1/3负空间。无浮动身份卡，无技能圆环。

中段：左边窄页边放章节名，右侧大范围给项目与正文；项目封面不是独立海报模板，而是该项目的“对象”：网站是窗口，文件工具是计划表。末尾版框打开成邮件入口的边界，形成第一次真正有意义的全站回扣。

### 排版与颜色

- 桌面12列、最大宽1320px；主要分割4/8列或5/7列，页边64–80px。手机4列、页边20–24px，使用新的构图而不是缩小桌面。
- 中文为语义主线，英文只做短章名：OPEN DRAFT / STARTING POINT / IN USE / BEFORE THE MOVE / STILL OPEN / WRITE BACK。英文可做背景展示层，但不能比中文更难读、更抢占信息。
- 统一系统无衬线字族：Arial、Noto Sans SC、Microsoft YaHei、PingFang SC的本地回退；不用一段衬线、一段等宽来制造“设计感”。代码示例才用等宽。
- 中文展示标题桌面88–128px、手机44–56px；正文17–18px；说明至少14px；元信息至少13px；操作文字15–16px。字重主要400/600/700三档，中文不使用极端负字距。
- 纸灰 `#F0EDE7`、墨黑 `#202323` 是阅读底色；氧化朱红 `#B84431` 只标示当前决定/关键动词；浅黄绿 `#D8E47B` 只用于少量“已核对”底块，底块上写深色字。不用所有章轮换背景色。颜色必须在实现时验收对比度，不能把色号当成已通过的结果。

### 动效语言

主动作只有三种：**错位→对齐、开口→展开、保留→补写**。滚动不是触发一段既定电影，而是允许观者在这几个关系之间往返。

首屏短pin，让错位的版框对齐；个人介绍保留阅读停顿；Web封面里的框展开成实际版式；Python流程让一行预览在确认区域之后进入分类结果；未实现项目只保留框线，不在滚动末尾伪装为完成；最后开口框成为邮件地址的下划线。

### 潜在缺点与约束

- 太多校样线、批注会变成“设计软件界面”。每场最多一个可解释的注释，不显示假的修订号、坐标、作者审阅章。
- “未定稿”可能被读成“不可靠”。真实项目标题、已实现状态、功能与边界必须先于主题修辞，工具不使用“安全无损”等绝对承诺。
- 不依赖旧稿截图：尚未整理版本截图时，使用原创版式模型并标注示意，不伪造“历史页面”。

## B · 路径之间 / IN BETWEEN

**一句话**：一个项目，把原本分开的知识连接起来。

### 核心创意

将主页组织成一张有实际含义的关系图：Sakura → C/C++/Python基础 → 现有作品；后端与AI Agent位于未闭合的探索路径。这里表达“知识如何在项目中相遇”，而非一份按熟练度排名的技能清单。

### 视觉母题、排版与颜色

视觉对象是**连续路径、交点与不同大小的文本区域**。线条必须有明确起点和终点，不能只是伪电路。姓名是源点，项目是可点击的终点，联系方式是开放出口。正文仍在常规文档流中，关系图是辅助阅读。

桌面采用跨栏连线与偏移标题，手机将路径折为一条纵向脊线；标签沿水平基线排列，不绕圆旋转。标题用中等字重的无衬线，避免浓缩海报字占满页面；一级文字48–80px，正文17–18px。

颜色：雾白 `#EFF2EE`、深松绿 `#143A35`、亮黄 `#DBE670`、少量陶土 `#AD513A`。深松绿承担大块背景，亮黄用于节点；配色服务关系层级，不能靠发光描边获得辨识度。

### 动效与叙事

滚动推进SVG路径描绘，分支遇到真实项目后展开其信息区域；上滚路径收回。项目卡不会沿路径飞行，避免读取移动目标。背景路径与前景标题的进度不同，但点击节点直接使用普通锚点，不强制沿整条路径走完。

### 潜在缺点

只有两个项目时关系图可能比内容复杂；线条容易被误读为已掌握技能之间的依赖或真实系统架构。增加项目会要求重新排线；手机容易退化成普通时间线。必须禁止用“完成点亮”来暗示尚未掌握的后端和Agent能力。

## C · 从局部看整体 / CHANGE OF SCALE

**一句话**：先把一个小问题看清，再理解它属于怎样的系统。

### 核心创意

用**二维取景口与尺度切换**组织网站。首屏只看一部分字形/版面；滚动拉开，出现身份与内容整体。进入项目再取一个真实局部：网页的导航问题、文件工具的预览计划。每次尺度变化都回答一个具体问题。

### 视觉母题、排版与颜色

母题是矩形视野、裁切边缘、一个固定的观察中心；不画显微镜、镜头标尺或“实验室”装置。大字允许被边缘截断，解释性文字始终处在独立清晰层。

桌面中心视野偏左，正文在右侧竖列；手机上视野与解释上下排列。英文标题偏窄、重字，中文短标题横向稳定；每场只对一个对象做尺度变化。

颜色：矿白 `#EEECE8`、深紫 `#312A56`、浅丁香 `#CAC3E2`、少量酸黄 `#DCE85E`。深紫用于“局部观察”，矿白用于“展开解释”，切换依据内容景别而非每章随机换肤。

### 动效与叙事

scrub驱动视窗从小局部放开到整体；相同矩形位置在章节之间接续，像二维graphic match。最多两次明显尺度变化，其余通过边界扩展而不是整个页面放大。正文、按钮、鼠标坐标系不缩放，不使用3D摄像机。

### 潜在缺点

如果没有真实截图/功能细节，容易变成“把字放大再缩小”的特效作品。尺度运动对部分用户不舒适，手机视野窄，减少动态效果模式与普通版本的差异会很大。最需要额外项目素材，也最容易用过长pin掩盖内容不足。

## 推荐A的理由

| 判断维度 | A 未定稿 | B 路径之间 | C 局部与整体 |
| --- | --- | --- | --- |
| 与当前两项目的联系 | 网站迭代、工具先预览再执行都有直接依据 | 跨技术联系可讲，但关系数量少 | 能讲局部决策，需要更多真实过程素材 |
| 文案可持续性 | 每个章节都有明确动词 | 容易反复使用“连接/路径” | 容易反复使用“看见/放大” |
| 滚动动作是否有语义 | 对齐、核对、展开对应真实开发动作 | 路径描绘有意义，但稍抽象 | 取景明确，过度缩放风险高 |
| 移动与静态降级 | 仍是一套有品质的编辑式页面 | 可降为纵向路径，但易普通 | 降级后最容易失去特色 |
| 后续维护 | 换项目内容即可沿用版框 | 新项目影响图结构 | 新项目需要重新设计观察点 |

**首选A，保留B/C作为完整备选，不把三者混装。** A不延续上版的“IDEAS INTO FORM＋切圆”；它以可核对的开发过程重建主题。其艺术指导目标是：无动画也像一份经过编辑的个人档案，有动画则让“修订与判断”被看见。

## 审查重点

这次需要审查的是主题是否像你、文案是否自然、六场叙事是否值得滚动，以及两处pin是否必要。A是推荐，不代表已经获得最终实施批准。若选B或C，下一轮须先重写对应分镜和文案，不能套用A的叙事只换颜色。
