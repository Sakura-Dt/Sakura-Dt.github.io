# TASK 02 · OPEN DRAFT 实现与验证

## 本轮实现

采用已确定的「未定稿 / OPEN DRAFT」：纸灰、墨色、朱红和少量黄绿；开口版框在标题、网页布局示意、文件预览和来信区域反复出现。新文案落在首页、时间线与两个详情页，学校、语言基础、探索方向、真实项目、邮箱及仓库链接保留。C++项目仍明确标记尚未实现。

六场包含：标题错位层随滚动对齐、个人介绍的基线延展、网页宽窄结构变化、文件预览/确认/移动与跳过示意、计划/学习记录的开放线尾、联系区域的版框展开。所有必需正文与操作不依赖动画解锁。

桌面宽≥1100且高≥720启用两处短sticky区间，额外距离分别0.70和0.60视口高度；手机、矮屏、减少动态效果与弱设备模式取消额外区间。手动“减少动效”入口可切换静态版。弱设备依据saveData、deviceMemory或hardwareConcurrency的低值作保守降级，不声称精确测出设备性能。

## 技术选择

重新阅读GSAP官方ScrollTrigger文档中的scrub、pin、timeline用法后，选择原生进度时间轴配合CSS sticky实现这六个有限场景。没有加入GSAP、CDN或平滑滚动库。选择理由是保持现有体积预算、静态部署和较小的维护面，并非声称GSAP性能差或无法胜任。

每场缓存起止位置，滚动只排队一次requestAnimationFrame写入transform/opacity；导航位置也缓存。布局只在resize、字体就绪、load、details、筛选及模式变更时测量。状态由当前滚动位置直接求得，不靠一次性onEnter累积，支持快滚、停滚及反向。

进度样本：桌面首屏0/25/50/75/100%再反向；相同50%处装饰层矩阵相同。流程舞台同样检查正反向，中点真实顶部维持导航下方约82px。减少动态效果恢复静态构图并取消区间高度，不只关闭transition。

## 内容维护

- `content/site.json`：集中所有可见文案、身份信息和详情说明；C编号与批准稿对应，其余为模板文字键。
- `templates/*.tpl`：页面结构、语义、资源与项目链接。
- `scripts/render_site.py`：标准库生成三个根目录HTML；`--check`验证内容源与发布文件一致。
- 生成HTML随源码保存，Pages直接读取；网站不在运行时fetch JSON，无JS也能阅读。
- CSS共享tokens与详情页在style.css，首页场景在home.css；交互和进度在main.js。
- CI新增生成结果一致性检查；没有修改远程、推送或部署。

文案有少量适配：保留明确的导航/分类/复制名称；“在线预览”写为“已发布版本”，避免把本地新版当已上线；详情技术说明按段落拆开，操作参数和工具限制不改。

维护命令：

```bash
python3 scripts/render_site.py
python3 scripts/render_site.py --check
python3 scripts/check_site.py
python3 -m unittest discover -s tests -p 'test_*.py' -v
npm test
```

本地静态预览仍为 `python3 -m http.server 8000 --bind 127.0.0.1`，打开 http://localhost:8000。查看改动后不要忘记同时保存内容源、模板和生成HTML。

## 真实视觉审查与修正

本地Edge / Playwright，1440×900与390×844。临时服务器和浏览器在检查后关闭；截图存于本次工作附件，不加入公开资源。

第一轮：检查三页首屏、全页滚动、项目details、学习记录和手机菜单。修正首屏纵向节奏偏松、筛选隐藏后resize可能留下旧文件移动距离、记录章节装饰线未接入进度的问题。

第二轮：对两处场景逐一采集0/25/50/75/100%及反向状态，并截图开始、中间、结束。发现最初用padding提供sticky区间没有真正固定，虽然进度数值正确，舞台仍移出视口并产生空白。改为真实内容高度区间，加入舞台中点位置断言后重新验证。进一步发现末态文件块盖住目标路径，增加目标框留白并计算纵向落点，复核文字不再互相覆盖。

最终复查：三个页面桌面/手机无横向溢出、页面脚本错误；顶部、中部、底部及展开状态实际查看。直接联系锚点在增强布局就绪后重定位，避免动态区间加入后偏移。无JS隐藏不可操作的筛选/复制按钮，原生导航、邮箱链接、项目链接和details仍保留。
