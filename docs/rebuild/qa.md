# 实际验收与交付

2026-10-30。执行环境：WSL Ubuntu 项目、Python 3.12 静态服务、Windows Node 24.15 与本机 Edge 156.0.4314.50，通过仓库 Playwright 1.62.1 控制真实浏览器。不是只读代码检查，也不是静态概念图。

## 两轮实际视觉审查与迭代

### 第一轮

启动本地 HTTP 服务。采集1440×900开场、about/web/python的0/50/100%、结尾；390×844首屏、全页以及两个详情页全页。实际打开并查看这些截图。

发现并修改：

1. 桌面首屏大字、正文与底部超出固定视口：降低字的纵向占比，重排正文间距，恢复底部入口与滚动提示。
2. 手机折面进入正文阅读区：重新安排折面位置，用同一纸白场形成明确的正文负形，保持全部文字的对比度。
3. 手机预览中字体与视窗比例不稳：采用预览容器相对字号，给窄视窗独立比例。

### 第二轮

重新采集1440×900三个后续核心场景的0/25/50/75/100%，开场与结尾、390×844首屏与全页。实际查看首屏、about末态、Web的25/50/100%、文件的50/75/100%、手机项目预览和三个流程按钮状态。不是根据进度数值推定画面。

继续发现并修改：

- 红底小字对比度4.25:1不足，正文墨色调深；三页最终axe扫描通过。
- 站标自定义名称未包含全部可见文字，移除多余aria-label，使用实际文字作为名称。
- 手机按钮点击导致浏览器自动滚动，旧scroll事件清除了刚设置的演示状态。改为仅在位置真正改变后解除手动状态，三步逐一实际截图确认。
- 320px详情页流程标题溢出，改为流式字号与间距。
- 1280×720首屏高度不足，降低矮屏英文尺寸；最终底部联系区底边正好处于720px，1440×900则为900px。
- 展示图与实际作品事实分开：Web图明确标注版式示意，Python图明确不操作用户文件；个人网站外链说明为已发布旧版。

## 滚动验证

四场：top、about、web、python。依次检查0/.25/.5/.75/1/.75/.5/.25/0。断言实际stage在导航下方78px，检查SVG d与CSS transform等真实状态在正反向同位置完全一致，不仅检查dataset数值。四场通过。

最终1440×900四场stage均822px，额外行程分别580/560/680/760px；about、web、python没有内部内容溢出。1280×720也复核；开场雕塑在视口边缘有少量有意裁切，正文与底部不裁切。移动端无pin额外占位。

没有接管wheel/touch滚动。普通锚点允许直接跳过演出；项目步骤按钮可直接查看状态，下一次实际滚动后恢复进度控制。

## 性能观察

在Edge无界面模式、6倍CPU减速下，执行90次滚动，每次等待两个requestAnimationFrame。最终采样均值约15.2ms、95百分位23.1ms。它是此环境的脚本与帧回调观察，不是手机真实帧率、60fps保证或Lighthouse分数。没有把屏幕录像采集开销混入结论。两核心模拟触发motion-mobile无固定模式。滚动控制器静止时不持续排帧，几何测量在布局变化后缓存。
