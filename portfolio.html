WEB / CASE 01 / FORM IN THE MAKING

一个入口，
多种阅读方式。

把真实资料组织成一个可用的网站，再让视觉叙事与阅读共存。

01
CONTEXT / 需求

先找到人，再读懂作品。

这是我的第一个 Web 项目。访问者需要快速了解我的背景、项目与联系方式；想深入的人，还能继续读需求、实现和边界。原生 HTML、CSS 与 JavaScript 保持静态部署，不需要后端或数据库。

ONE
CONTENT.
MANY WAYS TO READ.
STRUCTURE / 实现

内容先成立，演出再展开。

内容集中在 JSON，页面结构由模板生成根目录 HTML。GitHub Pages 直接提供静态结果；访问者不需要运行构建工具。

四个核心场景用滚动位置计算折面、文字与视窗状态。桌面采用有限的 sticky 区间，手机缩短停留并重新排列内容。没有滚轮劫持，也没有后台持续运转的动画循环。

移动导航、项目筛选、邮箱复制和原生详情展开各自独立。关闭 JavaScript 后，项目正文与链接仍然存在；减少动态效果时取消固定区间。

DECISIONS / 取舍

运动要解释内容。

折面 → 视窗
首屏的折面语言进入项目预览，桌面窗口收窄为手机比例，说明响应式布局。
演出 → 阅读
关键信息始终可读。折叠详情补充过程，直接入口允许跳过演出。
重构 → 可恢复
开发前保存既有工作快照，在独立分支验证；发布保留版本历史，便于恢复。
VALIDATION / 检查

把检查也放进工程。

静态检查验证资源、相对路径和锚点；浏览器测试检查响应式、交互、无脚本与减少动态效果。滚动时间轴在相同位置必须给出相同画面，正向和反向一致。

验收记录随源码保留，说明测试环境、检查范围与已知限制。浏览器模拟不能代替真实手机和人工读屏检查。
